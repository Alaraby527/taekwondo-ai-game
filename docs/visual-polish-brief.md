## 1. 项目现状（必读）

### 架构
- **纯前端、零依赖、零构建**。`index.html`（471 行）只有页面结构/样式/引导页 + 17 个 `<script>` 标签
- 游戏逻辑在 `js/` 下 17 个模块，**全部是 classic script，共享同一全局作用域**
- **绝对不要引入 ES Module / 打包器 / 外部库 / 图片素材**。原因：① 摊位要能离线跑；② 要能直接双击 `index.html` 用 `file://` 打开（`type="module"` 会让 `file://` 直接失效）；③ 音效是 Web Audio 代码合成的，就是因为"零素材"

### 渲染管线（`js/loop.js` 的 `frame()`）
```
① drawHall(t)        远景场馆：屏幕空间 + 视差 + LED 滚动 + 体积光锥
② drawFloorBase(t)   地面基色：屏幕空间，纯竖直渐变
③ camApply() → 世界层：drawArena / drawShadows / drawFighter / drawFx
④ drawHUD(t)         屏幕空间，独立 UI() 比例，不随相机抖动
```

### 世界坐标约定（**改视觉前必须理解，否则一定会画歪**）
- 原点 = 比赛区中心的地面点
- `wx` 场地横向（与 `f.x` 同义）；`wy` **离地高度，向上为正**（与 `f.y` 同义）
- 世界物体绘制时一律用 **`local y = -wy`**（高度向上 → 画布 y 减小）
- 取景全部经由相机：`camApply()`（世界层）、`projX/projY`（给 HUD 层投影飘字）
- 竖屏是「电影黑边 band」：逻辑视口 `H = SH - BAR_B`，游戏区**原点仍在 (0,0) 且与屏幕同宽**，所以世界层绘制不需要任何平移

### 美术基准（`js/stage.js`、`js/render-fighter.js`）
| 常量 | 值 | 含义 |
|---|---|---|
| `COURT` | 300 | 比赛区半径（世界单位） |
| `RING_OUT` | 384 | 出界线半径 |
| `ART_H` | 118 | 角色美术基准身高 |
| `HIP_Y` / `SHO_Y` | -54 / -98 | 髋、肩 |
| `HEAD_Y` / `HEAD_RX` / `HEAD_RY` | -115 / 7.6 / 8.6 | 头心与头半径 |
| `SHO_HW` / `HIP_HW` | 16.5 / 11 | 肩半宽 / 髋半宽 |

## 2. 本任务要解决的 8 个具体问题

> 每条都附「现象 → 文件位置 → 建议做法」。**不要只做颜色微调，这些是结构性的**。

### P1 手臂在实战架下读成"白团"（**优先级最高**）
- **现象**：腋下/胸前区域，近端臂与前臂护具叠成一块白色团块，看不出手臂结构。特写时尤其明显
- **位置**：`js/render-fighter.js` 的 `drawArm()` 与 `armPose` 分支（`backArm/frontArm`）
- **建议**：
  - 让上臂与前臂之间**留出可见的肘部转折**（当前肘关节球半径 2.4 偏小，且护具直接盖住转折）
  - 近端臂的护具不要与前臂同宽，收窄 15~20%，露出肘部
  - 拳套与护具之间加一道**暗缝**（`dk(fill,.3)` 的细描边），把两段分开
  - 考虑给近端臂加**投影到躯干上的接触阴影**，让它"浮"在躯干前面

### P2 观众席是重复圆点，不像人
- **现象**：`buildBg()` 里四排 `arc + quadraticCurveTo` 生成的剪影，间隔固定、形状重复，远看是一片圆点噪声
- **位置**：`js/scene.js` 的 `buildBg()`（"4) 观众席"段）
- **建议**：
  - 引入**伪随机但确定**的参数（用 `Math.sin(i*K)` 之类，避免 `Math.random()`，否则每次 `resize()` 都变）
  - 变化维度：头部半径、肩宽、倾斜、是否举起手臂、有无发光物（手机屏/荧光棒）
  - 近排剪影更实、远排更虚，并**越远越靠拢地平线**（当前四排的 `dy` 是硬编码常数）
  - 加极少量（<10 个）**高亮手机屏**，比大量等亮圆点更有"人"的感觉

### P3 道服没有布料感
- **现象**：躯干是平滑梯形 + 一条 V 领线，像塑料壳
- **位置**：`js/render-fighter.js` 躯干绘制段（`/* ---------- 躯干：道服 + 护甲 hogu ---------- */`）
- **建议**：
  - 在道服上补 2~3 条**褶皱**（沿受力方向：腋下横向、腰部纵向），用 `dk(cloth,.12)` 细线 + `lt(cloth,.3)` 反光配对
  - 下摆（髋部）做出**松量**：不要直线收口，用轻微外扩的曲线
  - 加**接触阴影**：hogu 下缘在道服上的投影、腰带对裤子的投影

### P4 打击感不够"重"
- **现象**：命中只有星芒 + 一个环，缺少方向性与分层
- **位置**：`js/fx.js`（`hitSpark`）、`js/render-fx.js`（`drawFx`）、`js/loop.js`（`CAM.hitZoom`）
- **建议**：
  - 星芒加**方向性**：沿攻击方向拉长的锥形白闪（而不是各向同性的星）
  - 分级：轻击（星芒）/ 重击（星芒 + 冲击环 + 短暂去色）/ 击倒（+ 全屏白闪，当前已有 `flashA`）
  - 加**命中定格**（已有 `hitStopT` 变量，确认是否真正生效；这是"重"的关键）
  - 地面扬尘：`dustRing()` 已有，但只在 axe 与 spinx 触发，可扩展到所有击倒

### P5 角色在实战尺寸下五官完全看不清（**设计取舍问题**）
- **现象**：整体取景（zoom 1.1~1.7）时角色高约 130~200px，脸上细节不可见
- **建议**：**不要加大五官细节**，而是**强化剪影识别度**：
  - 护头的前额开口包边加粗（这是"戴护具的人"最关键的识别特征）
  - 腰带与护具的颜色区分度再拉开
  - 拳套/脚背护垫在剪影上要能分辨（当前脚背护垫太小）
  - 出招时的**剪影夸张化**：踢击时腿的伸展可以比解剖学更夸张，剪影更"有戏"

### P6 场景上半部偏空、灯光层次单一
- **现象**：横竖屏都有大片深色区域，只有 `drawBeams()` 两束光
- **位置**：`js/scene.js`（`drawHall` / `drawBeams`）
- **建议**：
  - 加**轮廓光配色**：场馆主光是冷青，但地面应有**暖色反弹光**（低强度），冷暖对比能立刻提升质感
  - 聚光灯数量 2 → 4（两束跟人、两束固定打在场地两端）
  - 顶部桁架在 `H*0.05`，横屏时会被 HUD 挡住，考虑下移到 `H*0.09` 或把 HUD 做得更薄
  - 加**空气感**：极低透明度的体积雾分层（近层 0.02、远层 0.05）

### P7 没有地面反射
- **现象**：角色与竞技台之间缺少联系，角色像"贴"在图上
- **位置**：`js/render-fighter.js` 或 `js/scene.js` 的 `drawShadows()` 之后
- **建议**：在 `drawShadows()` 之后、角色之前，画一次**竖直镜像 + 严重压扁（0.28）+ 低透明度（0.10~0.16）** 的角色倒影。注意只在擂台范围内、并向远端渐隐。这是性价比极高的一项

### P8 触屏设备的操作提示是键盘文案
- **现象**：游戏区底部那行 `A/D 移动 · W/空格 跳 · …`，手机上无意义
- **位置**：`js/hud.js`（`drawHUD` 末尾的提示文本）
- **建议**：按 `isTouch()` 切换文案（触屏：`左下◀▶移动 · 右下跳/踢/挡 · 连点踢=旋风踢`）

## 3. 硬性约束（违反会导致返工）

1. **零构建、零外部依赖、零素材**。不允许引入 ES Module、npm 包、图片、字体文件、音频文件
2. **不要动玩法与数值**：`COURT`、`ART_H`、`f.h`、`f.w`、`RANKS.hp`、移动速度、命中判定都不改（视觉任务不碰平衡）
3. **不要动 `camApply` 的世界坐标约定**。如果你要加"透视地面"，**不要**改 `camApply`（它是仿射变换，无法产生透视收敛）；应该在**屏幕空间**额外绘制一套投影，见 `js/scene.js` 的 `drawFloorBase()` 思路
4. **帧循环是 try/catch 的**，出错会静默。**每改一处都要读 `window.__lastErr`**
5. **性能**：摊位是低端安卓机。单帧新增绘制预算参考：`drawFighter` 一次约 60~80 个 path 操作；倒影（P7）会让这个数字翻倍，如果掉帧就降到**每 2 帧更新一次倒影**
6. **改完必须同时验证横屏与竖屏**（`?vw=1100&vh=620` 与 `?vw=414&vh=896`）。竖屏是摊位主场景

## 7. 参考：如何自建截图对比

仓库里没有任何自动化测试。推荐的验证循环：

1. 起静态服务（`/workspaces/tmp/serve.sh`）
2. 用 `?vw=&vh=` + `__pause` + `__camOverride` 固定一个取景
3. 截图存档
4. 改代码 → 用**完全相同的取景**再截一次 → 并排比较

固定取景是重点：**取景一变，前后对比就没有意义了**。
