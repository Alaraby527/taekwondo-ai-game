# 跆拳道 · AI 对战（抖音校园 WowLand）

上海理工大学跆拳道社 × 抖音校园联合活动引导页 + 单人小游戏。

**一句话卖点**：操控选手，挑战会攻防、会闪避的 AI 跆拳道高手。严格按 **WT 竞技规则** 计分（拳躯干 1 分、踢躯干 2 分、踢头 3 分、旋转踢 +1），击倒后 8 秒读秒 KO，**五局三胜**，出界判罚对方 +1 分 —— 让同学在打斗中同时感受 **AI 的魅力** 和 **跆拳道的魅力**，最后引导关注抖音校园官方号。

## 渲染架构（视觉底座）

游戏采用 **2.5D 相机 + 世界坐标** 的渲染管线，这是后续所有视觉改动的基础：

```
远景场馆（屏幕空间 + 视差 + LED 滚动 + 体积光锥）
  → 地面基色（屏幕空间，纯竖直渐变）
    → 世界层（经 camApply() 统一变换：擂台 / 接触阴影 / 选手 / 特效）
      → HUD（屏幕空间，独立 UI() 比例，不随相机抖动）
```

**世界坐标约定**：原点 = 比赛区中心的地面点；`wx` 为场地横向，`wy` 为**离地高度（向上为正）**。绘制世界物体时一律用 `local y = -wy`。屏幕映射全部经由相机：

```js
camApply();                       // 之后所有绘制都在世界坐标里
const projX = wx => CX + CAM.shakeX + (wx - CAM.x) * CAM.zoom;   // 供 HUD 层投影飘字
const projY = wy => GROUND + CAM.shakeY - (wy - CAM.y) * CAM.zoom;
```

**相机**：跟随双方中点、按间距自适应推拉、命中瞬间推近、KO 慢推；**震屏已并入相机**（所以地面会抖、HUD 不会）。

**调试开关**（都只在显式使用时生效，不影响正常游玩）：

| 开关 | 用途 |
|---|---|
| `?vw=1280&vh=720` | 强制逻辑视口尺寸，用于校验横屏 / 竖屏取景 |
| `window.__pause = true` | 冻结模拟（保留绘制），便于自动化截图 |
| `window.__camOverride = {x, y, z}` | 锁定相机位置与缩放，用于取景 / 出图 |
| `window.__lastErr` | 最后一帧的异常堆栈（帧循环内部捕获，不中断游戏） |

## 游戏操作

| 平台 | 操作 |
|---|---|
| 电脑键盘 | `A`/`D` 左右移动 · `W`/`Space` 跳 · `J` 出拳 · `K` 踢腿 · `L` 格挡（按住） |
| 手机/平板 | 屏幕左下 ◀ ▶ 移动 · 右下 跳 / 踢 / 挡（触屏设备自动显示） |

### 炫技 / 连招

| 操作 | 效果 |
|---|---|
| 空中按 `K`（或跳起后点 踢） | **飞踢**：助跑起跳 → 腾空屈膝上提 → 空中出腿前伸，伤害更高、距离更远 |
| 快速连按 `K` 两下 | **下劈**：直腿从头上方劈下，踢头 3 分 |
| 快速连按 `K` 三下 | **旋风踢**（Tornado Kick）：撤步转身蓄力 → 转体 360° → 后腿横扫，范围大、伤害高、带残影与旋转特效 |
| 前进 + `K` | **侧踢**：前冲直线踹 |
| 后退 + `K` | **后踢**：转身后蹬，旋转技 3 分 |
| 连续命中对手（1 秒内再次命中） | **连招**：连击数叠加，每层 +14% 伤害，屏幕显示 `×N 连击` |
| `L`（或按住 挡） | 格挡：完全挡下对手攻击，不扣血 |

**小技巧**：AI 出手有前摇，看准时机反击；格挡能完全挡下攻击。段位越高 AI 越会预判格挡和闪避，黄带以上会用飞踢，绿带以上会旋风踢。被击倒后狂按 `J`/`K`（触屏狂点 踢）加速起身。

## 计分规则（WT 竞技规则）

| 得分部位 | 分数 |
|---|---|
| 拳击躯干 | 1 分 |
| 踢击躯干 | 2 分 |
| 踢击头部 | 3 分 |
| 旋转技（后踢/旋风踢） | +1 分加成 |

- **击倒（KO）**：血量归零后进入 **8 秒读秒**（屏幕大数字 + 圆环倒计时），读秒内按 `J`/`K` 加速起身，**起身回复 30% 血量**继续比赛；数完 8 秒没站起判 KO 负。读秒期间对方不得进攻（自动退开）。
- **三倒判负**：同一回合第 3 次被击倒，直接输掉该回合（防止无限起身拖时间）。
- **出界判罚**：完全越出赛场边界线 → 对方 +1 分，角色被弹回场内。
- 每回合 **60 秒**，时间到得分高者胜（平分判 AI 优势）。
- **五局三胜**：先拿下 3 回合者赢得对局；赢了晋级下一段位，输了留在当前段位重赛。

## 自定义调整（可选）

打开 `js/config.js`，`RANKS` 数组可调每个段位的 AI：

```js
{ name:'白带', color:'#e8eefc', ai:0.48, speed:1.05, hp:90,  tag:'新手 AI' }
```

- `ai`：AI 智能度（0~1，越高越会攻防/闪避/预判格挡）
- `speed`：移动速度倍率
- `hp`：每回合血量
- `name` / `color` / `tag`：段位名称、腰带颜色、简介

玩家/AI 攻击力在 `player` / `ai` 构造处调整（`attack`、`kickP` 出腿概率）——这两个实例在 `js/fighter.js` 底部。改完刷新即可。

## 已知事项

- 音效需用户与页面交互后（点击"开始挑战 AI"）才会初始化，符合浏览器自动播放策略。
- 触屏按钮仅在触屏设备（`pointer: coarse`）显示；竖屏游玩会提示建议横屏，可跳过。
- **段位进度不持久化**：`rankIdx` 是内存变量，刷新页面会回到白带（`v0-prompt.md` 里"persists in localStorage"的描述与实际代码不符，属于待实现项，不是已完成功能）。修复它 + 加埋点 + 二维码活码中间页 + 战绩海报分享属于下一轮"招新转化链路"。
- **竖屏上方仍有较大空白**：竖屏取景已从 `zoom 0.85` 提升到约 `1.17`（角色大约 40%），但侧视格斗在窄屏下横向受限，多出的竖向空间需要"竖屏专用布局（电影黑边 band）"才能根治，属下一轮"竖屏重排"。

### 已修复的历史缺陷（本次视觉底座重做）

| 缺陷 | 原因 |
|---|---|
| 命中粒子与扬尘绘制在屏幕外，打击时看不到碎屑 | 粒子按"离地高度"存储，却按屏幕坐标 `pt.y - GROUND + f.y` 绘制，实际落在 y≈−67 |
| LED 广告板滚动文字整段被裁掉 | `roundRect(x,y,w,h,r)` 使用全局 `ctx`，却按 `roundRect(ctx, ...)` 调用，裁剪路径变成 `NaN` |
| LED 文字位置横向偏出屏幕 | `bgLed.x` 含离屏缓存内边距，绘制时未扣除 `BG_PAD`（差 260px） |
| 游戏实际接近双倍速 | `requestAnimationFrame(loop)` 被启动两次，形成两条 rAF 链；而 `dt` 的 `|| .016` 兜底使第二次推进 16ms。现改为单次启动（实测 sim/真实时间比 0.95） |
