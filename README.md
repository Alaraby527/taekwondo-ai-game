# 跆拳道 · AI 对战（抖音校园 WowLand）

上海理工大学跆拳道社 × 抖音校园联合活动引导页 + 单人小游戏。

**一句话卖点**：操控选手，挑战会攻防、会闪避的 AI 跆拳道高手。严格按 **WT 竞技规则** 计分（拳躯干 1 分、踢躯干 2 分、踢头 3 分、旋转踢 +1），击倒后读秒、双方回角落、起身 1 秒无敌，**一局决胜**（30 秒），出界判罚对方 +1 分 —— 让同学在打斗中同时感受 **AI 的魅力** 和 **跆拳道的魅力**，最后引导关注抖音校园官方号。

## 渲染架构（视觉底座）

游戏采用 **2.5D 相机 + 世界坐标** 的渲染管线，这是后续所有视觉改动的基础：

```
远景场馆（屏幕空间 + 视差 + LED 滚动 + 体积光锥）
  → 地面基色（屏幕空间，纯竖直渐变）
    → 世界层（经 camApply() 统一变换：擂台 / 接触阴影 / 选手 / 特效）
      → HUD（屏幕空间，独立 UI() 比例，不随相机抖动）
```

**世界坐标约定**：原点 = 比赛区中心的地面点；`wx` 为场地横向，`wy` 为**离地高度（向上为正）**。绘制世界物体时一律用 `local y = -wy`。屏幕映射全部经由相机：

```js
camApply();                       // 之后所有绘制都在世界坐标里
const projX = wx => CX + CAM.shakeX + (wx - CAM.x) * CAM.zoom;   // 供 HUD 层投影飘字
const projY = wy => GROUND + CAM.shakeY - (wy - CAM.y) * CAM.zoom;
```

**相机**：跟随双方中点、按间距自适应推拉、命中瞬间推近、KO 慢推；**震屏已并入相机**（所以地面会抖、HUD 不会）。

**调试开关**（都只在显式使用时生效，不影响正常游玩）：

| 开关 | 用途 |
|---|---|
| `?vw=1280&vh=720` | 强制逻辑视口尺寸，用于校验横屏 / 竖屏取景 |
| `window.__pause = true` | 冻结模拟（保留绘制），便于自动化截图 |
| `window.__camOverride = {x, y, z}` | 锁定相机位置与缩放，用于取景 / 出图 |
| `window.__lastErr` | 最后一帧的异常堆栈（帧循环内部捕获，不中断游戏） |

## 游戏操作

| 平台 | 操作 |
|---|---|
| 电脑键盘 | `A`/`D` 左右移动 · `W`/`Space` 跳 · `J` 出拳 · `K` 踢腿 · `L` 格挡（按住） |
| 手机/平板 | 屏幕左下 ◀ ▶ 移动 · 右下 跳 / 踢 / 挡（触屏设备自动显示） |

### 炫技 / 连招

| 操作 | 效果 |
|---|---|
| 空中按 `K`（或跳起后点 踢） | **飞踢**：助跑起跳 → 腾空屈膝上提 → 空中出腿前伸，伤害更高、距离更远 |
| 快速连按 `K` 两下 | **下劈**：直腿从头上方劈下，踢头 3 分 |
| 快速连按 `K` 三下 | **旋风踢**（Tornado Kick）：撤步转身蓄力 → 转体 360° → 后腿横扫，范围大、伤害高、带残影与旋转特效 |
| 前进 + `K` | **侧踢**：前冲直线踹 |
| 后退 + `K` | **后踢**：转身后蹬，旋转技 3 分 |
| 连续命中对手（1 秒内再次命中） | **连招**：连击数叠加，每层 +14% 伤害，屏幕显示 `×N 连击` |
| `L`（或按住 挡） | 格挡：完全挡下对手攻击，不扣血 |

**小技巧**：AI 出手有前摇，看准时机反击；格挡能完全挡下攻击。段位越高 AI 越会预判格挡和闪避，黄带以上会用飞踢，绿带以上会旋风踢。被击倒后狂按 `J`/`K`（触屏狂点 踢）加速起身。

## 计分规则（WT 竞技规则）

| 得分部位 | 分数 |
|---|---|
| 拳击躯干 | 1 分 |
| 踢击躯干 | 2 分 |
| 踢击头部 | 3 分 |
| 旋转技（后踢/旋风踢） | +1 分加成 |

- **击倒（KO）**：血量归零后进入 **8 秒读秒**（屏幕大数字 + 圆环倒计时），读秒内按 `J`/`K` 加速起身，**起身回复 30% 血量**继续比赛；数完 8 秒没站起判 KO 负。读秒期间对方不得进攻（自动退开）。
- **三倒判负**：同一回合第 3 次被击倒，直接输掉该回合（防止无限起身拖时间）。
- **出界判罚**：完全越出赛场边界线 → 对方 +1 分，角色被弹回场内。
- 每回合 **60 秒**，时间到得分高者胜（平分判 AI 优势）。
- **一局决胜**：赢下这一局即可晋级下一段位，输了留在当前段位重赛。

## 自定义调整（可选）

打开 `js/config.js`，`RANKS` 数组可调每个段位的 AI：

```js
{ name:'白带', color:'#e8eefc', ai:0.46, speed:1.0,  hp:90,  riseTime:4.5, tag:'新手 AI' }
{ name:'黑带', color:'#1f2937', ai:1.0,  speed:1.75, hp:293, riseTime:0.5, tag:'宗师 AI' }   // 195 × 1.5
```

- `ai`：AI 智能度（0~1，越高越会攻防/闪避/预判格挡，并解锁防空对拼与两段式飞踢）
- `speed`：移动速度倍率
- `hp`：血量基准。**开局血量为 `hp × 0.7`**，且**双方相同**
- `riseTime`：被读秒后站起来的耗时（秒），段位越高越快（黑带 0.5s）
- `name` / `color` / `tag`：段位名称、腰带颜色、简介

> **黑带血量为其他段位曲线的 1.5 倍**（195 → 293，开局 205）。
> 注意 `startRound()` 给**双方同一个** `R().hp`，所以这 1.5 倍对玩家与 AI 同时生效。
> 若想要「只有黑带 AI 血厚」的非对称难度，需要改成分开赋值——目前不是这样。

玩家/AI 攻击力在 `player` / `ai` 构造处调整（`attack`、`kickP` 出腿概率）——这两个实例在 `js/fighter.js` 底部。改完刷新即可。

## 赛制：一局决胜

摊位场景的核心约束是**排队时必须快速出结果**，所以整场对局就是 **1 回合、30 秒**：

| 项 | 值 |
|---|---|
| 回合数 | **1 局定胜负** |
| 单局时长 | **30 秒**（时间到按 WT 得分判胜负，平分判 AI 优势） |
| 血量 | `RANKS.hp × 0.7` |
| 开局倒计时 | 2.4 秒（双方冻结） |
| 长期进度 | 赢则晋级下一段位（白→黑带六个段位），输则留在当前段位 |

- **每次从引导页点「开始挑战」都会重置**：回到白带起（摊位是共用设备，上一个人的进度不能留给下一个人）
- 段位进度写入 `localStorage`；引导页会在有存档时额外露出「继续上次 · X带」，供分享链接的家庭用户接着打
- 逻辑集中在 `js/round.js`：`WIN_NEED()` 恒为 1，`resetSession()` 负责复位

### 黑带宗师：Boss 局

黑带是最后一段，做成带二阶段的 Boss：

| 项 | 值 |
|---|---|
| 回合时长 | **前期 50 秒，超级复活决战重置为 60 秒** |
| 血量 | **293**（其余段位曲线的 1.5 倍），因此开局 **205** |
| **超级复活** | 黑带 AI **第 3 次被击倒时不判负**，而是：**满血复活** + **双方重置到开局站位** + **时间重置为 60 秒**，并**额外获得一次倒地机会**（`kdLimit` 3 → 4）。要打倒 **4 次**才真正判负 |
| 复活特效 | 金色横幅「超级复活！」+ 全屏白闪 + 慢动作 + 强震屏 + 双冲击环 + 92 个金/白粒子 + 2 秒无敌（护盾环提示） |
| 次数限制 | 每回合只触发一次（`superUsed`） |

**只对黑带 AI 生效，玩家的倒地规则完全不变**（仍是 3 次判负）。判定条件写在 `knockdown()` 里，
用 `isBoss = (t.side === 'a') && rankIdx >= RANKS.length - 1` 区分。

> **曾经把场地也翻倍，已回退。** 实测那是「纯缩放」而非玩法变化：
> 踢击判定距离约 152，而移动速度 / 攻击距离 / 出界余量（`obGrace` 固定 42）都没有变，
> 于是多出来的场地无人使用 —— 翻倍后两人占用半径反而从 **76% 掉到 34%**，
> 平均间距只从 83 变到 108，而镜头只框住两人，玩家根本感受不到。
> 结论：**只改 `COURT` 是加了一圈永久空置的地板**。要让场地"被感受到"必须从
> 镜头取景或玩法激励入手，不能只改尺寸。

### 击倒与起身

| 项 | 值 |
|---|---|
| 读秒 | 击倒后 8 秒读秒；**读秒期间双方固定在各自角落**（WT：回角落再继续），且不得进攻 |
| 玩家起身 | **7.0 秒**，且**速度逐渐增加**（前期慢、后期快）；狂按 J/K 可把倍率提到最高 6 倍 |
| AI 起身 | 按段位递减：白带 4.5s → 黄带 3.6 → 绿带 2.8 → 蓝带 2.0 → 红带 1.2 → **黑带 0.5s** |
| 起身无敌 | 站起后 **1 秒无敌**（有护盾环提示），避免刚站起来就连吃第二下 |
| 三倒判负 | 同一局第 3 次被击倒直接判负（现在这是主要的 KO 路径） |
| 起身回血 | 站起后血量至少恢复到 `maxHp × 30%` |

> 设计取舍：起身目标时间都小于 8 秒，所以**认真站起来不会被判 KO**——KO 主要来自比分落后与「三倒判负」。这样既保留了读秒的紧张感，又不会因为新人不懂「狂按」而被劝退。

## 竖屏布局：电影黑边 band

竖屏（摊位主场景，扫码进来基本全是竖屏）**不再提示"建议横屏"**——那句话在摊位上等于直接流失。现在竖屏会把游戏区限制在"电影黑边"内，底部黑边专门留给触屏按键：

```
┌──────────────┐
│   HUD（血条/得分/计时/赛制） │  ← 游戏区顶部
│                          │
│  擂台 band（W × H）        │  ← 逻辑视口 H = 屏幕高 − 底部黑边
│                          │
├──────────────────────────┤  ← 渐隐 + 细线分隔
│  ◀ ▶       跳 / 踢 / 挡   │  ← 底部黑边（触屏按键，CSS 百分比定位自动适配）
└──────────────┘
```

实现要点：游戏区**原点仍在 (0,0) 且与屏幕同宽**，所以不需要任何平移，只需把逻辑视口高度 `H` 改成 `SH - BAR_B`；`js/loop.js` 的 `frame()` 负责先铺黑边底色、再把游戏层裁进 `(0,0,W,H)`。触屏按键本来就是 CSS 百分比定位，因此**无需改动**。

效果：竖屏相机 zoom 从 `0.85`（被下限夹住）提升到 **约 1.70**，角色占游戏区高度约 30%。

## AI 对手架构：Jev 战术层 + 本地反射层

AI 对手的「战术」由一个真实 AI 服务（TypeSafe Jev）决定，而「反射动作」由本地代码执行：

| 层 | 位置 | 职责 | 频率 |
|---|---|---|---|
| 战术层 | `server/jev-proxy` → Jev | 选战术（突进/游走/反击/防守/假动作）、预判对手是否即将出腿 | 每 1.4 秒（约 20~40 次/局） |
| 反射层 | `js/ai.js` | 移动、出招时机、前后摇、命中判定、格挡 | 每帧 |

分两层的原因：Jev 实测 **236~698ms/次**，做不到 60fps 逐帧决策。

**核心约束：反射层就是降级方案。** 没网 / 代理未配 / 超预算 / 超时 → 前端静默退回纯本地 AI（`bias` 全为中性，行为与纯本地一致），**游戏永远能玩，不是"有网才好用"**。

前端把 Jev 返回的**概率分布**当作行为混合权重（而非硬切换），动作更平滑。注意 `confidence` 实测常只有 0.28~0.49，**不要拿它当降级开关**。

接入配置（`js/jev.js` 的解析顺序）：

1. `?jev=https://...` —— 联调临时切换
2. `<meta name="jev-base" content="https://...">` —— **反代配好后填这里**
3. 同源（默认）

代理的部署、接口、成本闸门与性能数据见 **`server/jev-proxy/README.md`**。

## 招新转化链路

目标是「招到新人」，所以除了游戏本身，还需要**可度量**与**可回访**：

### 埋点（无需额外后端）

复用 Jev 代理新增的 `/track` 端点收集漏斗，**不需要再起一个后端**：

```
landing_view → start_game → round_end → match_end → match_win / match_lose
```

- 端点：`POST /track`（追加 JSONL）、`GET /stats`（按事件聚合，可直接看漏斗）
- 数据落在 `server/jev-proxy/data/events.jsonl`
- 前端 `js/track.js`：**用 `text/plain` 发送**（CORS 安全列表内类型 → **完全绕开预检**，省一次往返且不依赖服务端 OPTIONS 实现）
- **失败静默忽略**，埋点绝不影响游戏
- 地址解析：`<meta name="track-base">` → 跟随 `jev-base` → 同源

**隐私**：默认**不记录客户端 IP**（校园活动可能涉及未成年，IP 属个人信息）。服务端还会丢弃前端误传的 `ua`/`referer`/`email`/`phone`/`name`。确有需要时用 `TRACK_STORE_IP=1` 显式打开。

### 段位持久化（原先完全缺失）

`js/persist.js` 用 `localStorage` 存 `rankIdx` / `winStreak` / 访问与对局计数。

这里有个**设计张力**：摊位是**共用设备**，上一个人的进度不该留给下一个人；但分享链接的**家庭用户**希望下次回来能接着打。所以：

| 入口 | 语义 |
|---|---|
| 「开始挑战 AI」 | **全新开始**（摊位语义：速战 + 白带起） |
| 「继续上次 · X带」 | **恢复进度**（家庭用户语义；有存档时才露出，且直接进入正式赛） |

`resetSession()` 挂在「开始挑战」上，所以共用设备不会互相污染；存档只在「继续上次」被显式消费。

## 战斗手感与平衡（本轮调整）

### 飞踢不再是「赖皮技」

原来的飞踢接近零风险高收益：落地的 `freeze` 只有 **0.08s**，而 `cool=1.1` 在那段约 1 秒的滞空里**早已走完**，所以落地可立刻再起跳；再加上伤害 ×1.35、判定算头部（3 分）、前冲 520 横跨大半场地。

| 项 | 改前 | 改后 |
|---|---|---|
| 落地硬直 | 0.08s | **0.40s**（真实的被反击窗口） |
| 落地后冷却 | ≈0（滞空中已走完） | **≥0.55s** |
| 伤害倍率 | ×1.35 | ×1.15 |
| 前冲距离 | 520 | 400 |

现在飞踢仍然是强力接近技，但落地会被惩罚——尤其面对会防空的 AI。

### AI 不再「挨打不还手」

根因很有意思：`!p.grounded` 这个判断**同时包含「倒地」和「腾空」**，所以玩家一跳起来 AI 只会以固定 90 的速度慢慢后退、既不会格挡也不会反击——飞踢自然一打一个准。

新增三层反应（都体现在 `js/ai.js`）：

1. **防空（按段位分两种）**
   - **红带 / 黑带（skill ≥ 0.8）**：**不后退**，趁对手起跳与滞空阶段直接**对拼抢伤害**——对手在空中同样吃判定，先手出腿能「偷」到分，也就不必离开边界
   - **中低段位**：以**格挡**为主（飞踢是头击 3 分，挡下收益最大），否则后撤让对手落空；
     **贴边没有后撤空间时强制改为格挡**
2. **抓落地**：记录对手「刚落地」事件，在其 0.40s 落地硬直内获得 0.5s 的惩罚窗口，优先出手
3. **抓收招**：对手出招结束后的冷却期也是可惩罚窗口（`p.cool > 0.18`），此时不再用随机数决定，而是果断出手

实测（玩家反复朝 AI 飞踢冲来）：

| 段位 | 前压帧 | 后退帧 | 出招帧 | 全程最高 \|x\| |
|---|---|---|---|---|
| **黑带** | **17** | **0** | 4 | 130 |
| 白带 | 0 | 11 | 0 | 199 |

黑带全程不后退，并在对手起跳阶段抢到 35 分；边界上限是 342，两者都远未逼近。

### 出界保护（对所有分支生效）

`aiThink` 开头定义 `guardOut(vx)`：AI 处于界边（`COURT + 42 − 50`）且目标速度朝外时把速度归零。所有 `targetVx` 赋值都过这个函数——**包括会提前 `return` 的防空分支**。这既修了「Jev 给 `defend` 时 AI 自己走出界白送分」的缺陷，也保证防空后撤不会退出边界。

### Jev 战术层引入的一个平衡缺陷（已修）

Jev 给出 `defend` 时会拉大保持距离，反射层一路后退 → 贴到界边仍继续向外 → **自己被判出界，白送对手 +1 分**。实测「玩家挂机不动却能拿 7 分」就是这么来的。现在 `aiThink` 末尾加了出界保护：处于界边且目标速度朝外时把速度归零。

### 决战前的积分分配

Boss 超级复活时，会弹出**增益分配面板**——把你在黑带第一阶段打出的 WT 得分换成决战底牌：

```
可分配大分 = floor(黑带第一阶段的得分 / 5)      // 每 5 分 = 1 个大分
```

| 增益 | 效果 |
|---|---|
| 铁壁 | 血量上限 +30%（立即回满） |
| 重击 | 造成的伤害 +25% |
| 不倒 | 额外获得一次倒地机会 |
| 坚韧 | 起身更快（起身耗时 −40%） |

每个消耗 1 个大分，**可重复选取**（点数多于选项数时不浪费）。

**时序**（这里有个必须遵守的约束）：

```
Boss 第 3 次倒地 → 当帧立即冻结 + 立即弹面板 → 玩家兑换 → 确认 → 出场演出 → 最终决战
```

- **必须在复活当帧就冻结**。曾经用 `simLater` 延后 1.2 秒再弹面板，那 1.2 秒里模拟照跑，
  玩家可以自由移动（实测确认的 bug）
- **演出必须放在「确认」之后**。因为冻结期间 `update()` 不推进，
  把白闪/粒子放在复活瞬间只会定格成一帧静止画面，而且 `flashA` 不衰减会一直白屏
- **输入要在入口拦，不能只靠 `update()` 冻结**：`holdBlock()` / `setJump()` 是直接改状态的
  （不走 `update`），所以 `js/input.js` 提供了 `inputLocked()`，键盘、触屏、这两个函数都过它
  （注意：读秒期不算锁定，那时玩家正要狂按 J/K 起身）
- 面板/结算期间返回首页也要收掉面板并解除冻结（`showHome()`）

## 已知事项

- **相机必须居中于双方中点，不要再加横向夹取**：`updateCam()` 里曾经有
  `CAM.tx = clamp(midX, ±COURT*0.5)`，两人都在墙角时中点可达 ±642，
  镜头被夹在中场 → **有一个人跑出画面**（场地翻倍后更明显）。
  中点本身必然落在场地内，不需要额外限制；zoom 下限也压到 0.2，
  否则间距大时拉不开、同样会有人出画。已用「横竖屏 × 8 种位置组合」穷举验证。
- 代价：竖屏 + 场地翻倍 + 两人分处两端时，zoom 会降到约 0.30（角色约 35px 高）。
  这是「两个人必须都看得见」的必然取舍；AI 靠近后会自动拉回。
- **时间一律用「仿真时间」，不要用 `performance.now()`**：`js/util.js` 提供 `SIM_T` 与
  `simLater(fn, delay)`（仿真时间调度器）。原因是出招状态切换与命中判定必须同一个时钟——
  原实现混用 `setTimeout`（真实时间）清状态、用 `stT`（仿真时间）判命中，
  在低帧率或标签页被节流时两者会脱节：状态先被清掉、命中窗口还没打开，**攻击静默落空**
  （实测仿真仅真实时间 0.25 倍时，攻击 100% 打不中；低端手机上同理）。
  新增任何延时逻辑请用 `simLater`，不要用 `setTimeout`。
- 音效需用户与页面交互后（点击"开始挑战 AI"）才会初始化，符合浏览器自动播放策略。
- 触屏按钮仅在触屏设备（`pointer: coarse`）显示；竖屏游玩会提示建议横屏，可跳过。
- **段位进度不持久化**：`rankIdx` 是内存变量，刷新页面会回到白带（`v0-prompt.md` 里"persists in localStorage"的描述与实际代码不符，属于待实现项，不是已完成功能）。修复它 + 加埋点 + 二维码活码中间页 + 战绩海报分享属于"招新转化链路"。
- **二维码直指微信群**：群码会过期（打印物料还在、码已失效），且"扫码"这一步无法统计。需要改成中间页活码，属"招新转化链路"。
- **触屏按键文案仍是键盘提示**：游戏区底部那行 `A/D 移动 · W/空格 跳 · …` 是键盘说明，在手机上无意义，待按设备类型切换。

### 已修复的历史缺陷（本次视觉底座重做）

| 缺陷 | 原因 |
|---|---|
| 命中粒子与扬尘绘制在屏幕外，打击时看不到碎屑 | 粒子按"离地高度"存储，却按屏幕坐标 `pt.y - GROUND + f.y` 绘制，实际落在 y≈−67 |
| LED 广告板滚动文字整段被裁掉 | `roundRect(x,y,w,h,r)` 使用全局 `ctx`，却按 `roundRect(ctx, ...)` 调用，裁剪路径变成 `NaN` |
| LED 文字位置横向偏出屏幕 | `bgLed.x` 含离屏缓存内边距，绘制时未扣除 `BG_PAD`（差 260px） |
| 游戏实际接近双倍速 | `requestAnimationFrame(loop)` 被启动两次，形成两条 rAF 链；而 `dt` 的 `|| .016` 兜底使第二次推进 16ms。现改为单次启动（实测 sim/真实时间比 0.95） |
