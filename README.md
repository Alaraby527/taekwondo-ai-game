# 跆拳道 · AI 对战（抖音校园 WowLand）

上海理工大学跆拳道社 × 抖音校园联合活动引导页 + 单人小游戏。

**一句话卖点**：操控选手，挑战会攻防、会闪避的 AI 跆拳道高手。严格按 **WT 竞技规则** 计分（拳躯干 1 分、踢躯干 2 分、踢头 3 分、旋转踢 +1），击倒后 8 秒读秒 KO，**五局三胜**，出界判罚对方 +1 分 —— 让同学在打斗中同时感受 **AI 的魅力** 和 **跆拳道的魅力**，最后引导关注抖音校园官方号。

## 渲染架构（视觉底座）

游戏采用 **2.5D 相机 + 世界坐标** 的渲染管线，这是后续所有视觉改动的基础：

```
远景场馆（屏幕空间 + 视差 + LED 滚动 + 体积光锥）
  → 地面基色（屏幕空间，纯竖直渐变）
    → 世界层（经 camApply() 统一变换：擂台 / 接触阴影 / 选手 / 特效）
      → HUD（屏幕空间，独立 UI() 比例，不随相机抖动）
```

**世界坐标约定**：原点 = 比赛区中心的地面点；`wx` 为场地横向，`wy` 为**离地高度（向上为正）**。绘制世界物体时一律用 `local y = -wy`。屏幕映射全部经由相机：

```js
camApply();                       // 之后所有绘制都在世界坐标里
const projX = wx => CX + CAM.shakeX + (wx - CAM.x) * CAM.zoom;   // 供 HUD 层投影飘字
const projY = wy => GROUND + CAM.shakeY - (wy - CAM.y) * CAM.zoom;
```

**相机**：跟随双方中点、按间距自适应推拉、命中瞬间推近、KO 慢推；**震屏已并入相机**（所以地面会抖、HUD 不会）。

**调试开关**（都只在显式使用时生效，不影响正常游玩）：

| 开关 | 用途 |
|---|---|
| `?vw=1280&vh=720` | 强制逻辑视口尺寸，用于校验横屏 / 竖屏取景 |
| `window.__pause = true` | 冻结模拟（保留绘制），便于自动化截图 |
| `window.__camOverride = {x, y, z}` | 锁定相机位置与缩放，用于取景 / 出图 |
| `window.__lastErr` | 最后一帧的异常堆栈（帧循环内部捕获，不中断游戏） |

## 游戏操作

| 平台 | 操作 |
|---|---|
| 电脑键盘 | `A`/`D` 左右移动 · `W`/`Space` 跳 · `J` 出拳 · `K` 踢腿 · `L` 格挡（按住） |
| 手机/平板 | 屏幕左下 ◀ ▶ 移动 · 右下 跳 / 踢 / 挡（触屏设备自动显示） |

### 炫技 / 连招

| 操作 | 效果 |
|---|---|
| 空中按 `K`（或跳起后点 踢） | **飞踢**：助跑起跳 → 腾空屈膝上提 → 空中出腿前伸，伤害更高、距离更远 |
| 快速连按 `K` 两下 | **下劈**：直腿从头上方劈下，踢头 3 分 |
| 快速连按 `K` 三下 | **旋风踢**（Tornado Kick）：撤步转身蓄力 → 转体 360° → 后腿横扫，范围大、伤害高、带残影与旋转特效 |
| 前进 + `K` | **侧踢**：前冲直线踹 |
| 后退 + `K` | **后踢**：转身后蹬，旋转技 3 分 |
| 连续命中对手（1 秒内再次命中） | **连招**：连击数叠加，每层 +14% 伤害，屏幕显示 `×N 连击` |
| `L`（或按住 挡） | 格挡：完全挡下对手攻击，不扣血 |

**小技巧**：AI 出手有前摇，看准时机反击；格挡能完全挡下攻击。段位越高 AI 越会预判格挡和闪避，黄带以上会用飞踢，绿带以上会旋风踢。被击倒后狂按 `J`/`K`（触屏狂点 踢）加速起身。

## 计分规则（WT 竞技规则）

| 得分部位 | 分数 |
|---|---|
| 拳击躯干 | 1 分 |
| 踢击躯干 | 2 分 |
| 踢击头部 | 3 分 |
| 旋转技（后踢/旋风踢） | +1 分加成 |

- **击倒（KO）**：血量归零后进入 **8 秒读秒**（屏幕大数字 + 圆环倒计时），读秒内按 `J`/`K` 加速起身，**起身回复 30% 血量**继续比赛；数完 8 秒没站起判 KO 负。读秒期间对方不得进攻（自动退开）。
- **三倒判负**：同一回合第 3 次被击倒，直接输掉该回合（防止无限起身拖时间）。
- **出界判罚**：完全越出赛场边界线 → 对方 +1 分，角色被弹回场内。
- 每回合 **60 秒**，时间到得分高者胜（平分判 AI 优势）。
- **五局三胜**：先拿下 3 回合者赢得对局；赢了晋级下一段位，输了留在当前段位重赛。

## 自定义调整（可选）

打开 `js/config.js`，`RANKS` 数组可调每个段位的 AI：

```js
{ name:'白带', color:'#e8eefc', ai:0.48, speed:1.05, hp:90,  tag:'新手 AI' }
```

- `ai`：AI 智能度（0~1，越高越会攻防/闪避/预判格挡）
- `speed`：移动速度倍率
- `hp`：每回合血量
- `name` / `color` / `tag`：段位名称、腰带颜色、简介

玩家/AI 攻击力在 `player` / `ai` 构造处调整（`attack`、`kickP` 出腿概率）——这两个实例在 `js/fighter.js` 底部。改完刷新即可。

## 赛制：速战单局 / 正式赛

摊位场景的核心约束是**排队时必须在 90 秒内出结果**，所以默认赛制是速战：

| 模式 | 触发 | 回合 | 单回合时长 | 血量 | 获胜条件 |
|---|---|---|---|---|---|
| **速战单局** | 从引导页进入（默认） | 1 局定胜负 | 30 秒 | `RANKS.hp × 0.65` | 先得分高者胜 |
| **正式赛** | 速战获胜后自动解锁 | 五局三胜 | 60 秒 | `RANKS.hp` | 先拿 3 局 |

- 速战获胜 → 晋级下一段位 **并解锁正式赛**（结束面板按钮变为"进入正式赛 · 五局三胜"）
- **每次从引导页点"开始挑战"都会重置**：回到速战模式 + 白带起（摊位是共用设备，上一个人的进度不能留给下一个人）
- 逻辑集中在 `js/round.js`：`WIN_NEED()` 返回当前赛制所需胜局，`quickMode` 标记模式，`resetSession()` 负责复位

## 竖屏布局：电影黑边 band

竖屏（摊位主场景，扫码进来基本全是竖屏）**不再提示"建议横屏"**——那句话在摊位上等于直接流失。现在竖屏会把游戏区限制在"电影黑边"内，底部黑边专门留给触屏按键：

```
┌──────────────┐
│   HUD（血条/得分/计时/赛制） │  ← 游戏区顶部
│                          │
│  擂台 band（W × H）        │  ← 逻辑视口 H = 屏幕高 − 底部黑边
│                          │
├──────────────────────────┤  ← 渐隐 + 细线分隔
│  ◀ ▶       跳 / 踢 / 挡   │  ← 底部黑边（触屏按键，CSS 百分比定位自动适配）
└──────────────┘
```

实现要点：游戏区**原点仍在 (0,0) 且与屏幕同宽**，所以不需要任何平移，只需把逻辑视口高度 `H` 改成 `SH - BAR_B`；`js/loop.js` 的 `frame()` 负责先铺黑边底色、再把游戏层裁进 `(0,0,W,H)`。触屏按键本来就是 CSS 百分比定位，因此**无需改动**。

效果：竖屏相机 zoom 从 `0.85`（被下限夹住）提升到 **约 1.70**，角色占游戏区高度约 30%。

## AI 对手架构：Jev 战术层 + 本地反射层

AI 对手的「战术」由一个真实 AI 服务（TypeSafe Jev）决定，而「反射动作」由本地代码执行：

| 层 | 位置 | 职责 | 频率 |
|---|---|---|---|
| 战术层 | `server/jev-proxy` → Jev | 选战术（突进/游走/反击/防守/假动作）、预判对手是否即将出腿 | 每 1.4 秒（约 20~40 次/局） |
| 反射层 | `js/ai.js` | 移动、出招时机、前后摇、命中判定、格挡 | 每帧 |

分两层的原因：Jev 实测 **236~698ms/次**，做不到 60fps 逐帧决策。

**核心约束：反射层就是降级方案。** 没网 / 代理未配 / 超预算 / 超时 → 前端静默退回纯本地 AI（`bias` 全为中性，行为与纯本地一致），**游戏永远能玩，不是"有网才好用"**。

前端把 Jev 返回的**概率分布**当作行为混合权重（而非硬切换），动作更平滑。注意 `confidence` 实测常只有 0.28~0.49，**不要拿它当降级开关**。

接入配置（`js/jev.js` 的解析顺序）：

1. `?jev=https://...` —— 联调临时切换
2. `<meta name="jev-base" content="https://...">` —— **反代配好后填这里**
3. 同源（默认）

代理的部署、接口、成本闸门与性能数据见 **`server/jev-proxy/README.md`**。

## 招新转化链路

目标是「招到新人」，所以除了游戏本身，还需要**可度量**与**可回访**：

### 埋点（无需额外后端）

复用 Jev 代理新增的 `/track` 端点收集漏斗，**不需要再起一个后端**：

```
landing_view → start_game → round_end → match_end → match_win / match_lose
```

- 端点：`POST /track`（追加 JSONL）、`GET /stats`（按事件聚合，可直接看漏斗）
- 数据落在 `server/jev-proxy/data/events.jsonl`
- 前端 `js/track.js`：**用 `text/plain` 发送**（CORS 安全列表内类型 → **完全绕开预检**，省一次往返且不依赖服务端 OPTIONS 实现）
- **失败静默忽略**，埋点绝不影响游戏
- 地址解析：`<meta name="track-base">` → 跟随 `jev-base` → 同源

**隐私**：默认**不记录客户端 IP**（校园活动可能涉及未成年，IP 属个人信息）。服务端还会丢弃前端误传的 `ua`/`referer`/`email`/`phone`/`name`。确有需要时用 `TRACK_STORE_IP=1` 显式打开。

### 段位持久化（原先完全缺失）

`js/persist.js` 用 `localStorage` 存 `rankIdx` / `winStreak` / 访问与对局计数。

这里有个**设计张力**：摊位是**共用设备**，上一个人的进度不该留给下一个人；但分享链接的**家庭用户**希望下次回来能接着打。所以：

| 入口 | 语义 |
|---|---|
| 「开始挑战 AI」 | **全新开始**（摊位语义：速战 + 白带起） |
| 「继续上次 · X带」 | **恢复进度**（家庭用户语义；有存档时才露出，且直接进入正式赛） |

`resetSession()` 挂在「开始挑战」上，所以共用设备不会互相污染；存档只在「继续上次」被显式消费。

## 已知事项

- 音效需用户与页面交互后（点击"开始挑战 AI"）才会初始化，符合浏览器自动播放策略。
- 触屏按钮仅在触屏设备（`pointer: coarse`）显示；竖屏游玩会提示建议横屏，可跳过。
- **段位进度不持久化**：`rankIdx` 是内存变量，刷新页面会回到白带（`v0-prompt.md` 里"persists in localStorage"的描述与实际代码不符，属于待实现项，不是已完成功能）。修复它 + 加埋点 + 二维码活码中间页 + 战绩海报分享属于"招新转化链路"。
- **二维码直指微信群**：群码会过期（打印物料还在、码已失效），且"扫码"这一步无法统计。需要改成中间页活码，属"招新转化链路"。
- **触屏按键文案仍是键盘提示**：游戏区底部那行 `A/D 移动 · W/空格 跳 · …` 是键盘说明，在手机上无意义，待按设备类型切换。

### 已修复的历史缺陷（本次视觉底座重做）

| 缺陷 | 原因 |

| 命中粒子与扬尘绘制在屏幕外，打击时看不到碎屑 | 粒子按"离地高度"存储，却按屏幕坐标 `pt.y - GROUND + f.y` 绘制，实际落在 y≈−67 |
